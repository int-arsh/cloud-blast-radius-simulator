# Terraform Plan JSON Support Specification

## 1. Supported Formats and Versions

The parser ingests the official machine-readable JSON representation generated by:
```bash
terraform plan -out=tfplan.binary
terraform show -json tfplan.binary > tfplan.json
```

### Verified Format Versions
- **Format Version Range:** Supported major versions `0.x` and `1.x` (target standard: `format_version: "1.2"`).
- **Terraform CLI Compatibility:** Terraform v0.12 through v1.15+.
- Plans with unverified major versions (e.g., `99.0`) trigger explicit warnings while attempting structural recovery.

---

## 2. Lifecycle Actions and Normalization

Terraform represents actions as an array of lowercase strings (`change.actions`). The simulator maps these deterministically into `NormalizedAction` enum values:

| Raw Plan Action Array | Normalized Action | Destructive? | Meaning |
| :--- | :--- | :--- | :--- |
| `["create"]` | `create` | No | New resource to be provisioned |
| `["update"]` | `update` | No | In-place attribute modification |
| `["delete"]` | `delete` | **Yes** | Resource slated for destruction |
| `["delete", "create"]` | `replace` | **Yes** | Destroy-then-create replacement |
| `["create", "delete"]` | `replace` | **Yes** | Create-before-destroy replacement |
| `["no-op"]` | `no-op` | No | Unchanged resource state |
| `["read"]` | `read` | No | Data source read operation |
| *Any other combination* | `unsupported` | No | Unrecognized state; yields parsing warning |

---

## 3. Dependency Provenance Extraction

Dependencies are extracted from two configuration blocks to ensure complete dependency visibility:

1. **Explicit Configuration Dependencies (`depends_on`):**
   - Extracted directly from `configuration.root_module.resources[].depends_on`.
2. **Expression References (`expressions.*.references`):**
   - References like `aws_db_instance.primary.endpoint` are resolved to the canonical resource address `aws_db_instance.primary`.
   - Variable (`var.*`), local (`local.*`), and count (`count.*`) expressions are safely filtered out.

---

## 4. Secret Masking and Safety Guarantees

Before storing or analyzing resource snapshots:
- Attributes in `change.before` and `change.after` pass through the recursive secret redactor.
- Sensitive attributes (passwords, tokens, API keys, private keys, certificates) are permanently masked as `"[REDACTED]"`.
- Sensitive attributes are never printed in logs or propagated to API clients.

| :--- | :--- |

| `malformed.json` | Unclosed JSON syntax error handling |
| `unsupported_version.json` | Verification of warning generation on unknown format versions |
| `unsupported_action.json` | Graceful classification of unrecognized action combinations |
